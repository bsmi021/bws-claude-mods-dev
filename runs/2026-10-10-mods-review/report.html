Verdict per mod

Key findings

  1. bug

    Finish-Line blocks the supervisor for the worker's tasks

    13 of 17 open-item blocks were in sessions that never touched the folder. A harness worker wrote it after the session started, so the mtime rule claimed it. 8 of the 17 blocks bought no tool call, only a restated reply.

    Detail

    The one win: the motion-capture session on 10-06. After the block came 30 tool calls of real work on items that didn't need you: hand tracking, a faster pose model and a metrics script. Then a commit and a marked checklist. Keep that behavior.

    Missed hand-backs: 3 replies were real hand-backs: "Tell me when it's plugged in" and "say go and I'll…" twice. They have no question mark and none of the listed phrases. Items that start with Brian: or (proposed-task) also held the stop open. Widen the list to imperative asks only. "Say if you want a different order" is the reply the guard rightly pushed past.

    Evidence check: it fired 13 times and was wrong each time. The replies were "holding for master", "nothing committed yet" and "waiting on the GDD agent". "done" matched status text. 10 fires were bws-game-tms agent-team sessions. Teammate messages count as prompts, so they keep resetting the 2-block cap.

    Fix 1: claim a run folder only when this session's Edit, Write or Bash input names it. Fix 2: recognize "tell me / say go / say if / when you next ask" as hand-backs, and treat items that start with the owner's name or (proposed-task) as parked. Fix 3: set evidenceCheck to false by default. Receipts: receipts/finish_guard_detail.json.

  2. gap

    Shell Lint lets 5 too-long commands through

    5 heredocs sized 7725–7843 failed with "unexpected EOF". The limit is 7850. Passing commands reach 7802, so lowering the limit alone can't separate them.

    Detail

    Adding a count of " and \ to the metric (length + 3×' + " + \) and setting the limit at 7800 catches all 5. It would refuse 1 passing command in the 7300–7850 sample. The sample is small, so replay over the full corpus before shipping. Receipt: receipts/lint-threshold.txt. It also caught a probe of mine this session, with the right fix.

  3. bug

    Guard re-blocked a launch that had the fix

    On 10-06 the tms-heim promo render was blocked for low VRAM. The retry added the exact -ini overrides inside a PowerShell $args array and was blocked again. The model then found another route.

    Detail

    -ArgumentList $args hides the arguments from the Start-Process check. Pass the launch when t.MaxFPS=30 or the override string appears anywhere in the command. Also, a HighResShot promo render at 50% screen percentage is the wrong trade, and you asked twice for "full settings". Exempt -unattended render runs, or respect an explicit r.ScreenPercentage. The other 4 blocks (adb, Unity not running, unreal-mcp down, missing -automated) were correct.

  4. new

    Editor contention is the biggest unowned pain

    About 15 prompts deal with editors: "when the editor is free", "close every other UnrealEditor", "why is the loop running tests in the wrong editor", "stop restarting Unity". Sessions also traded "taking" and "free" messages by hand to take turns pushing.

    Proposed mod: Editor lease

    A session or loop claims the UE editor, a Unity project or git push through a lease in $.store. The guard then blocks editor kill, restart and launch, and MCP builder calls, while another session holds the lease, and names the holder. The band shows who holds it. It extends the existing guard. Drop the Repo Sessions pane and its tasklist poll, but keep the session-registry parsing in peers.ts for the lease. Scope it in an interview first: which resources, how long a lease lasts, and how harness.py claims one.

  5. route

    Headless waits fail in a chain, but it's not a mod job

    Workers hit the built-in sleep block 174 times. The Monitor calls that followed failed with "schema was not sent" 79 times. 77 shell calls ran into the 10-minute cap, 38 of them wait loops.

    Detail

    Monitor is a deferred tool, and workers call it without loading it. The cheap fix is one line in the harness-loop worker prompt: load Monitor with ToolSearch before using it, and use run_in_background for long waits. A mod that refuses an unloaded Monitor call with that hint first needs a probe showing tool.call runs before input validation. Separately, 13 writes went ungranted in one pit-maneuver worker, which is an allowlist problem.
