## Decisions you must know (all recorded as assumptions A1 to A5 on the dashboard)
- **A1, headless (a spec conflict).** FR-PB-02 says skip headless runs, but AC-PB-01 needs a `claude -p` refusal under
  `block`. So: `warn` skips a run with no surface (it has no pane for "send anyway"); `block` checks headless prompts and
  refuses them with the reason. If Brian wants block to skip headless too, change `skipReason` and the headless test, and
  AC-PB-01 must then be verified interactively only.
- **A2, origins.** Only `composer`, `bridge` and `sdk` prompts are checked. Plugin, peer, schedule, task and
  auto-continuation prompts pass unchanged. The bouncer's own Send anyway arrives as `plugin` and is never re-checked.
- **A3, `/bounce` is per session.** It sets the `setting` atom and does not write the plugin options or settings (FR-ALL-07).
- **A4, `bounceModel` is a new option.** It keeps the enhancer's `model` option meaning what it did (FR-ALL-06 wants a model option).
- **A5, pastes.** The engine expands pastes before `prompt.submit`, so only leftover placeholders and attachments are
  skipped. A long pasted log is checked as ordinary text.
- **Reason call system text.** classify-fork's request type has no `system` field, and the kit is not changed for this.
  So `REASON_SYSTEM` goes in front of the prompt (the adapter passes it through unchanged).
- **Timeouts.** `$.model.classify` and `$.model.fork` have no signal. The 4 s timeout is a race (`bound`), so a late
  answer is ignored; the reason call (`$.model.complete`) gets a real abort signal from the same 4 s timer.
- **Block hint.** A headless block says `Edit it and send it again.`; an interactive one says the pane's buttons.
- **Summary chip.** The atom is published (FR-ALL-05), but bws-cockpit draws only the four names in its `modSummaries`
  option, so no chip shows for bws-enhance. Changing that default is a cockpit change, not this mod's. It is parked as a
  shelved idea.

## Watch out for
- `claude plugin validate` reports `gating hook without .catch: prompt.submit` (and the existing enhance and ui.close
  hooks). `bounceCheck` catches its own errors and returns null, so a throw cannot hold a prompt. The advice does not change the verdict.
- The kit copies in `hooks/kit/` are generated. Run `python tools/sync-kit.py --plugin bws-enhance --check` after any kit change.
- Module variables `bounceOption`, `bounceModel` and `glossaryOption` are set in `register` on every load. Tests rely on that.
- The 15 manual checks have not been run in a real terminal. The pane focus, the `s`/`e`/`x` keys and the narrow-terminal
  behaviour are unverified.
