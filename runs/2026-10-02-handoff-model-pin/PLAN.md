## Mechanism (checked in the 2.1.287 types)
- `$.model.fork({ prompt })`: one tool-less question over this session's own transcript (same model and system prompt, served from the prompt cache). It returns `isAnswered` + `text`, or a `reason` (`nothing-to-fork`, `api-error`, `empty-reply`, `aborted`).
- `$.ui.copy({ text })` puts text on the clipboard.
- `agent.spawn`: input has `subagentType`, `model` (the Agent tool's `model` as given, or undefined), `parentModel` and `fork`. `next({ ...e, model })` picks the subagent's model. Forks always inherit, so `model` is ignored for them.

## Finish line (all true, receipts in this folder)
1. **`/handoff [focus]`** writes a handoff for a fresh agent, generated by `$.model.fork` from this session's transcript, into `<run folder>/HANDOFF.md`.
   - The run folder is the one written this session; if there is none, a new `runs/<YYYY-MM-DD>-handoff/`.
   - Sections: Objective, Finish line, Done so far (with receipts), Next step, Open items, Key files and commands, Decisions and constraints, Watch out for.
   - Under about 450 words, with exact paths, hashes and commands. Nothing invented.
   - Optional focus text steers it.
2. **An existing HANDOFF.md is kept,** as `HANDOFF.<yyyymmdd-hhmm>.md`, before the new one is written.
3. **Start prompt on the clipboard.** `/handoff` copies a short start prompt for the next session ("Read <path>/HANDOFF.md first ... then continue from its next step"). The reply shows the path, the start prompt and whether it was copied.
   - Without a clipboard (headless), the reply still shows the start prompt.
4. **Failures are clear:** nothing to hand off yet, or an API error / empty reply. No file is written.
5. **Worker model pin.** When `workerModel` is set, every subagent spawn without an explicit `model` runs on it, for the types listed in `workerAgentTypes` (default `general-purpose,claude`). A toast names the model.
   - An explicit `model` in the Agent call still wins: "unless the task is complex".
   - Forks, other types (Explore, Plan, plugin agents with their own model) and explicit models are untouched.
   - Default `workerModel` is "" (off), so the published plugin changes nothing.
6. **Brian's settings:** `pluginConfigs["bws-cockpit"].options.workerModel = "claude-sonnet-5-5"`, with a backup first. This is what he asked for repeatedly.
